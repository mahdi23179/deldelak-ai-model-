## ۲) Gateway — node --test

اجرا: `cd gateway && node --test test/controller.test.mjs` → **۱۷ از ۱۷ پاس** در ~۶ ثانیه
شواهد خام: `docs/evidence/gateway-node-tests.txt`

سناریوهای واقعی که این تست‌ها شبیه‌سازی و تأیید می‌کنند:

1. Cold start: درخواست در صف می‌ماند، بیدارسازی یک‌بار انجام می‌شود و پاسخ **واقعی** به همان درخواست برمی‌گردد.
2. Timeout صف: 503 صادقانه + `Retry-After` + `request_id`؛ درخواست پس از آماده‌شدن همچنان اجرا می‌شود.
3. همزمانی: درخواست‌های موازی دقیقاً **یک** بیدارسازی.trigger می‌کنند و صف مشترک دارند.
4. `X-Request-Id` تکراری دوبار اجرا نمی‌شود.
5. کلید نامعتبر **قبل از** بیدارسازی رد می‌شود (هیچ هزینه‌ای تحمیل نمی‌شود).
6. ترتیب واقعی وضعیت‌ها: `WAKING → STARTING → LOADING_MODEL → READY`.
7. Timeout بیدارسازی → 504 `wake_timeout` + وضعیت ERROR (بدون موفقیت صوری).
8. شکست API گیت‌هاب → 502 برای صف + ثبت `last_error`.
9. خاموشی خودکار فقط وقتی که idle است **و** بک‌اند BUSY نیست؛ درخواست جدید در لحظهٔ خاموشی، آن را لغو می‌کند.
10. شکست stop گیت‌هاب ثبت و قابل مشاهده می‌شود؛ وضعیت به READY برمی‌گردد.
11. Deep health بدون بیدارسازی، وضعیت واقعی را گزارش می‌کند.
12. Stream به‌صورت chunk-by-chunk عبور می‌کند و در شمارندهٔ in-flight آزاد می‌شود.
13. endpoint وضعیت درخواست: رؤیت درخواست‌های صف‌شده، 404 برای id ناشناس.
14. endpointهای داخلی با shared secret محافظت می‌شوند؛ ثبت key-hash باعث رد سریع کلید غلط در لبه می‌شود.
