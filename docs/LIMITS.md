# محدودیت‌های واقعی GitHub Codespaces (صادقانه و بدون دور زدن)

این پروژه هیچ محدودیتی را دور نمی‌زند. اعداد رسمی GitHub برای پلن Free (حساب شخصی):

| مورد | مقدار |
|---|---|
| سهمیه محاسبه | **۱۲۰ ساعت-هسته در ماه** |
| با ماشین ۲ هسته‌ای (basicLinux32gb) | ≈ **۶۰ ساعت روشن‌ماندن در ماه** |
| ذخیره‌سازی | **۱۵ گیگابایت-ماه** (مدل ~۲GB + سیستم ≈ ۱۲GB) |
| خاموشی خودکار | پس از **۳۰ دقیقه خلوتی** (پیش‌فرض) |
| حداکثر idle timeout | **۲۴۰ دقیقه** |
| GPU | ندارد (پروژه هم GPU نمی‌خواهد — llama.cpp روی CPU) |
| توقف در پایان ماه | سرویس تا شروع دوره بعد متوقف می‌شود |

## پیامدها برای دلدلک

1. **۲۴/۷ روشن‌ماندن با پلن رایگان ممکن نیست.** اگر ربات را دائم روشن نگه دارید، سهمیه ۶۰ ساعته در ~۲.۵ روز تمام می‌شود. راه درست: خاموشی خودکار + **Auto-Wake** (روشن‌شدن با درخواست).
2. **سرعت واقعی CPU:** برای مدل ۳B کوانتیزه Q4_K_M روی ۲ هسته، انتظار ~۵ تا ۱۰ توکن بر ثانیه. اعداد اندازه‌گیری‌شده در `docs/TEST_REPORT.md`.
3. **رم:** مدل ~۲GB فایل + زمینه 4K → مصرف llama-server حدود ۲.۵ تا ۳GB از ۸GB. کافی است ولی برای تسک‌های موازی سنگین نیست — به همین دلیل اجرای عامل **تک‌نوبتی** است.
4. **ذخیره‌سازی:** بار اول ~۱۲GB مصرف می‌شود (mirror + ابزار + مدل). زیر سقف ۳۲GB دیسک کداسپیس است ولی بالای سهمیه ۱۵GB-ماه؛ اگر کداسپیس را نگه دارید ممکن است هزینه ذخیره‌سازی کمی صادر شود — کداسپیس را حذف کنید تا صفر شود (مدل دوباره بارگیری می‌شود).
5. **آدرس عمومی پورت** با حذف/بازسازی کداسپیس عوض می‌شود (نام تصادفی). workflow بیدارسازی هر بار لینک تازه می‌دهد.

## تنظیمات پیشنهادی کاربر

- Settings → Codespaces → Default idle timeout: **240 minutes**
- برای صرفه‌جویی: کداسپیس‌های استفاده‌نشده را از https://github.com/codespaces **Stop** کنید (نه حذف — مدل کش می‌ماند).
